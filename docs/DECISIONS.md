# Architecture Decisions

Short log of load-bearing decisions. Full plan history lives with the repo owner.

1. **Supabase + catalog snapshot** — Postgres is the source of truth; the pipeline compiles a gzipped `catalog.json` published to Supabase Storage. The app bundles a snapshot in the APK, checks a tiny `meta.json` on launch, and downloads only on version change. Offline-first, ~zero egress, survives free-tier pauses.
2. **Seeds-as-curation** — journeys/stages/ordering live in `seed/*.yaml`, validated in CI. No admin UI. Merge precedence: seeds > site > YouTube.
3. **No auth in MVP** — progress is device-local (drift/SQLite) with `updated_at`/`synced_at` columns so Phase 2 anonymous-auth sync is additive. No login wall.
4. **YouTube TOS compliance** — playback exclusively via the official embedded player (`youtube_player_iframe`). No downloading/ripping, no background YouTube audio. Phase 2 audio uses binothaimeen.net-hosted files only.
5. **MVP ingests YouTube only** — the binothaimeen.net site adapter is an enrichment layer behind an interface, deferred past MVP. Raw responses get snapshotted so parser breakage is loud.
6. **Arabic-only, RTL-first** — `supportedLocales: [ar]`, `EdgeInsetsDirectional` everywhere, bundled IBM Plex Sans Arabic, dark mode from day one.
7. **Audio-only for now** (2026-07-29) — the app ships the foundation's audio library only; video is off. Decided at the *catalog* layer, not in the app: `npm run publish:catalog -- --audio-only` drops the video series, re-points journey stages at their audio companions, and promotes those companions to browsable. Costs nothing — the YouTube uploads are clips, so audio covers the same material with more hours (692.1h vs 478.7h). The player/PiP/webview code stays in place, dormant; re-enabling video is a publish without the flag. See CURATION.md.
8. **Read-along sentence times are measured** (2026-07-30, superseding the estimate that shipped a day earlier) — the site timestamps markers, never sentences, and the median lesson has a 34-minute gap between them, so interpolation drifted by minutes. `tools/align` runs wav2vec2 CTC forced alignment over the audio: median error 1.26s by hold-out validation. Scripts still ship as per-lesson gzipped assets (~5 MiB), never in `catalog.json` or drift. Unaligned lessons keep an interpolated time, clamped so they can never precede a measured neighbour. **Never score alignment against markers the aligner used as segment boundaries** — that is circular; use `validate_holdout.py --drop-one`. See CURATION.md and tools/align/README.md.
9. **Offline downloads** (2026-07-29) — audio lessons can be stored on device: a `downloads` user table (never touched by catalog imports) plus files under Application Support, not Documents, since this is re-downloadable content. The queue runs strictly one at a time — a زاد المستقنع book is up to 392 lessons and racing them would saturate the connection and stampede the foundation's server. Rows keep the basename only, because iOS relocates the app container between installs; a `.part` file is renamed into place only once complete, so a half-file can't be mistaken for a finished download. Wi-Fi only by default (`connectivity_plus`), re-checked per lesson so a series download can't silently continue onto mobile data.
10. **Loudness levelled, not boosted** (2026-07-29) — measured per lesson (`analyze:loudness`) and corrected toward −16 LUFS. Attenuation works everywhere; boost only on Android via `AndroidLoudnessEnhancer`, because iOS clamps `AVPlayer.volume` at 1.0× and just_audio has no Darwin effects. So the app fixes lesson-to-lesson *inconsistency* — the actual complaint — rather than making quiet lessons louder on iPhone. Sources peak at ≈−2 dBFS, so there's no headroom for a naive digital boost either; a native AVAudioEngine path with a limiter is the upgrade, and `gain_db` is already there for it.
11. **No lesson dates shown** (2026-07-31, reasoning corrected same day) — the app displays no date. The first version of this entry said no per-lesson date existed; that was wrong, and worth recording because the mistake was methodological: only the fields our parser stores were checked, not the API's full response. Two dates exist per lesson. `created_at` is the bulk-upload stamp and is identical (2022-04-05) on all 500. `publish_date` — which `site.ts` does not read — is real and varies, incrementing daily: رياض from 2011-10-14, كتاب التوحيد from 2008-11-24, كتاب الصلاة from 2014-09-21. But those are the foundation's upload schedule, years after the sheikh died in 2001, so they are publication dates and not when a lesson was taught. Showing one would invite exactly the wrong reading. If a real teaching date is ever wanted it has to be curated by hand; nothing upstream carries it.
12. **Scholar named in the UI, matn author left blank** (2026-07-31) — reverses the earlier "per-scholar UI deferred until a second scholar ships": the point is attribution, not disambiguation, so «الشارح» is named on the resume card and in «عن الكتاب». «المؤلف» is a separate field because the sheikh teaches from books he mostly did not write — and it ships EMPTY. The foundation publishes no author anywhere: no book endpoint (book_library/written_library/matn_library all return empty; the route accepts any type), a sitemap of only voice_library and Levels lesson pages, no author field on section or lesson objects, and empty `attachments`. Values must therefore be curated against a citable source and approved before shipping — an omitted attribution is recoverable, a wrong one in a da'wah app is not.
13. **App identity** — app name «مسار طالب العلم», Dart package `masar`, applicationId / bundle id `app.masar.talib` on both stores (FINAL, decided 2026-07-17: sheikh-neutral because the roadmap adds more sheikhs; unchangeable after the first store upload). The first content pillar remains Sheikh Ibn Uthaymeen with full attribution.
14. **Plural in the UI, not just the schema** (2026-07-31) — the name and bundle id were chosen sheikh-neutral (13), but the screens read as an Ibn Uthaymeen app: ~15 strings said «المؤسسة» and «الشيخ» in the definite singular, and Settings hardcoded one foundation and `binothaimeen.net`. The data was already plural and simply unread. Implemented from the design's own unbuilt multi-sheikh sheets (`docs/design/masar-screens.dc.html` 3a, 3b, 4b, 4d–4f): a `ScholarAvatar` roundel + name on series cards, the resume card, the player and «عن الكتاب»; a scholar page at `/scholar/:slug` carrying his own «جميع المواد بإذن …» line; المكتبة → الشيوخ as a second browse axis; and الإعدادات → المصادر والإسناد as a list of foundations rather than one credit. The splash names no foundation — it renders before the catalog loads, so it *cannot* be data-driven, and with several scholars there is no single rights holder to name app-wide. `scholars.status: coming_soon` (ابن باز, seeded 2026-07-31 with no series) makes browsing-by-scholar a real axis rather than a list of one; publishing rejects a coming-soon scholar who has series, and an active one who has none. **Not built**: the design's sheikh *filter* chips (3a, 4e) — filtering across one scholar-with-content is noise; they earn their place when a second scholar actually ships lessons. Also not built, being separate features rather than attribution: follow/«متابَع», fatwa-of-the-day, the ملاحظاتي tab, anonymous sync. Scholar birth/death dates and birthplace (design 4b) stay omitted for the same reason as 12 — no source.
15. **A second scholar's content, and a second validation method** (2026-07-31) — ابن باز goes from announced to real: «مسار العقيدة بشرح ابن باز» (شرح كتاب التوحيد 75 دروس + شرح العقيدة الطحاوية 32) from binbaz.org.sa. That site has no JSON API, so `tools/ingest/src/binbaz.ts` scrapes it — but it implements the **existing** `SiteClient` interface, so `syncSiteAudio`, `mergeAudioLessons` and the idempotency contract are reused rather than duplicated; a series' `audio_source` picks the client. Two traps worth keeping written down. (a) **Pagination only works on the canonical URL**: the router resolves a series by id, so page 1 renders under any slug, but `?page=2` on a placeholder silently re-serves page 1 — a 75-lesson series synced as 15 and looked like a short series, not a bug. The client now reads `<link rel="canonical">` out of page 1 first. (b) **The site publishes no timestamps at all**, so read-along times can only come from forced alignment, and `validate_holdout.py --drop-one` has nothing to hold out — the 1.26 s median in 8 cannot be reproduced or measured here. `tools/align/validate_decode.py` scores it from the audio instead (cut at the aligned time → CTC-decode → CER against the sentence). **The measurement said no, so the مسار ships audio-only** (`read_along: false` on both series; the transcripts and the 15,242 measured times stay in the data files, so reversing it is a rebuild rather than a re-ingest). Two things about how that was established are worth keeping, because both nearly produced the wrong answer. (i) A 16-sentence sample put binbaz at 0.522 against a 0.467 control and looked fine; at 96 sentences it was 0.708 vs 0.601 with p90 1.207 vs 0.844. Do not call this gate on a small sample. (ii) Comparing CER **across** sources confounds alignment quality with audio quality — Ibn Baz's recordings are older and decode worse however well they are timed. The measure that settles it is within-source: score each sentence again at t+45s, where it is known to be wrong, and look at the gap. Trusted source **+0.197**, binbaz **+0.069** — binbaz timestamps carry about a third of the signal, barely better than a deliberately wrong guess. Journeys are now attributed too, because «مسار العقيدة» exists twice: `JourneySummary.scholarSlugs` is **derived** by `GROUP_CONCAT(DISTINCT scholar_slug)` over the stages' series rather than seeded, so it cannot drift from what the journey teaches.
16. **The app icon is rendered from the design, not drawn** (2026-07-31) — `tools/icon/` re-renders design section 2a (the «مسار» wordmark in a double gold ring on the green gradient) with headless Chrome, using the app's own bundled Amiri, so the shipped mark cannot drift from the design file. The `--refine` pass is load-bearing, not polish: the icon generators derive every size by downscaling the 1024 master, and below 120px «طالب العلم» stops being a word and becomes grey noise — so all 17 sub-120px icons are re-rendered from the roundel-only variant, laid out at the target size rather than downscaled. The design says the same thing («Wordmark drops "طالب العلم" below 120px»).
