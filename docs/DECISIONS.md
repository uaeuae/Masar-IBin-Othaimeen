# Architecture Decisions

Short log of load-bearing decisions. Full plan history lives with the repo owner.

1. **Supabase + catalog snapshot** — Postgres is the source of truth; the pipeline compiles a gzipped `catalog.json` published to Supabase Storage. The app bundles a snapshot in the APK, checks a tiny `meta.json` on launch, and downloads only on version change. Offline-first, ~zero egress, survives free-tier pauses.
2. **Seeds-as-curation** — journeys/stages/ordering live in `seed/*.yaml`, validated in CI. No admin UI. Merge precedence: seeds > site > YouTube.
3. **No auth in MVP** — progress is device-local (drift/SQLite) with `updated_at`/`synced_at` columns so Phase 2 anonymous-auth sync is additive. No login wall.
4. **YouTube TOS compliance** — playback exclusively via the official embedded player (`youtube_player_iframe`). No downloading/ripping, no background YouTube audio. Phase 2 audio uses binothaimeen.net-hosted files only.
5. **MVP ingests YouTube only** — the binothaimeen.net site adapter is an enrichment layer behind an interface, deferred past MVP. Raw responses get snapshotted so parser breakage is loud.
6. **Arabic-only, RTL-first** — `supportedLocales: [ar]`, `EdgeInsetsDirectional` everywhere, bundled IBM Plex Sans Arabic, dark mode from day one.
7. **Audio-only for now** (2026-07-29) — the app ships the foundation's audio library only; video is off. Decided at the *catalog* layer, not in the app: `npm run publish:catalog -- --audio-only` drops the video series, re-points journey stages at their audio companions, and promotes those companions to browsable. Costs nothing — the YouTube uploads are clips, so audio covers the same material with more hours (692.1h vs 478.7h). The player/PiP/webview code stays in place, dormant; re-enabling video is a publish without the flag. See CURATION.md.
8. **Read-along sentence times are estimated** (2026-07-29) — the foundation's site timestamps markers, never sentences, so `build-texts` interpolates between the markers it can anchor in the transcript. Exact at each section start, ~±30s in between; the UI says «مزامنة تقريبية» rather than implying precision, and offers tap-to-seek + long-press-to-re-anchor. Scripts ship as per-lesson gzipped assets (~5 MiB), never in `catalog.json` or drift. Forced alignment is the upgrade path and needs no app change. See CURATION.md.
9. **Offline downloads** (2026-07-29) — audio lessons can be stored on device: a `downloads` user table (never touched by catalog imports) plus files under Application Support, not Documents, since this is re-downloadable content. The queue runs strictly one at a time — a زاد المستقنع book is up to 392 lessons and racing them would saturate the connection and stampede the foundation's server. Rows keep the basename only, because iOS relocates the app container between installs; a `.part` file is renamed into place only once complete, so a half-file can't be mistaken for a finished download. Wi-Fi only by default (`connectivity_plus`), re-checked per lesson so a series download can't silently continue onto mobile data.
10. **Loudness levelled, not boosted** (2026-07-29) — measured per lesson (`analyze:loudness`) and corrected toward −16 LUFS. Attenuation works everywhere; boost only on Android via `AndroidLoudnessEnhancer`, because iOS clamps `AVPlayer.volume` at 1.0× and just_audio has no Darwin effects. So the app fixes lesson-to-lesson *inconsistency* — the actual complaint — rather than making quiet lessons louder on iPhone. Sources peak at ≈−2 dBFS, so there's no headroom for a naive digital boost either; a native AVAudioEngine path with a limiter is the upgrade, and `gain_db` is already there for it.
11. **App identity** — app name «مسار طالب العلم», Dart package `masar`, applicationId / bundle id `app.masar.talib` on both stores (FINAL, decided 2026-07-17: sheikh-neutral because the roadmap adds more sheikhs; unchangeable after the first store upload). The first content pillar remains Sheikh Ibn Uthaymeen with full attribution.
